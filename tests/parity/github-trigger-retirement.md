# GitHub trigger backend test retirement

Seven TypeScript backend suites were retired after their useful contracts moved to native Rust tests. The native tests use a disposable database, HTTP routes, and a fake GitHub HTTP server. They do not launch the TypeScript backend or contact GitHub.

| Former suite | Native replacement |
| --- | --- |
| `github-triggers.test.ts` | `integrations::github_triggers::tests::routes_create_disabled_rules_check_without_tasks_and_scope_access` checks route authorization, disabled rule creation, revision conflict, archive, and activity; `captured_local_authority_ignores_display_metadata_but_rechecks_execution_facts` checks effective project, preset, profile, actor, and company authority without treating display metadata as a gate; `preview_records_exclusions_failures_and_the_latest_provider_retry`, `enabled_rule_pass_excludes_ineligible_pull_requests_without_dispatch_or_task`, and `unavailable_github_access_records_the_provider_error_on_every_due_rule` check candidate outcomes and failure persistence. |
| `github-trigger-admission.test.ts` | `admission_capture_stores_its_exact_request_and_profiles_and_links_its_task` checks the pinned request, profile snapshots, source drift, dispatch-link failure and transaction rollback of task, issue number, and audit event. |
| `github-trigger-dispatch-service.test.ts` | `enabled_rule_pass_excludes_ineligible_pull_requests_without_dispatch_or_task` and `admission_capture_stores_its_exact_request_and_profiles_and_links_its_task` cover final eligibility and exact task capture. The persisted dispatch and task are checked through native database reads. |
| `github-trigger-dispatches.test.ts` | `dispatch_capture_is_immutable_and_links_only_its_exact_task` checks repeated preparation, immutable retry input, contradictory source, task binding, delivery policy and push idempotence; `admission_capture_stores_its_exact_request_and_profiles_and_links_its_task` checks request/profile bytes and a grouped matrix of mismatched task source, delivery target, hash, creator, status, and profile. |
| `github-trigger-inspection.test.ts` | `inspection_pages_files_rechecks_the_revision_and_rejects_malformed_data`, `inspection_reads_every_file_page_through_the_three_thousand_file_limit`, `labelled_issue_pages_keep_only_pull_requests_and_reject_later_failures`, and `github_triggers_inspection::tests::pull_recheck_uses_immutable_identity_and_revision_but_returns_current_metadata` cover paginated GitHub facts, revision drift, malformed data, and final metadata. |
| `github-trigger-paths.test.ts` | `github_triggers_inspection::tests::protected_paths_are_exact_files_or_directory_prefixes` and `unsafe_protected_paths_and_filenames_are_rejected` cover exact files, renamed paths, case-sensitive directories, and unsafe path forms. |
| `github-trigger-poller.test.ts` | `poller_waits_after_each_pass_and_stops_after_an_in_flight_pass` and `poller_retries_after_a_failed_pass` check cadence, shutdown, and retry. |

The native check path reads current GitHub and database authority. Candidate observations and saved dispatches remain evidence of prior inspection; they do not authorize task creation when the source or current rule has changed.
