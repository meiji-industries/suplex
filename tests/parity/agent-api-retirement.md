# Agent API backend test retirement

`tests/agent-api.test.ts` exercised the retired TypeScript task host. Its 61 cases are replaced by native checks at the same authority boundaries. The Rust tests use a paired bearer credential, a real HTTP listener, a disposable SQLite database, and a disposable Git repository where those systems affect the result.

| Former cases | Native check |
| --- | --- |
| Public map, OpenAPI contract, credential states, board-session isolation, pairing persistence, project grants, discovery scope and pagination | `rust/tests/routes/agent_api.rs`: public-map journey, rejected credentials, identity/capabilities, creation, and task read/list/conditional polling tests; `rust/src/identity/external_agents.rs` pairing, grant, rotation and revocation tests; `rust/tests/contract_parity.rs` frozen wire schemas. |
| Create validation, project policy, workflow/template/profile/attachment choices, dry runs, source errors and provider failures, project isolation | `rust/tests/routes/agent_api.rs`: creation validation/dry run, scoped discovery, dependency scope, source and policy cases; `rust/src/tasks/sources.rs` source resolution tests and `rust/src/tasks/agent_api.rs` admission tests. |
| Idempotency, legacy hashes, semantic omission versus empty description, concurrent creation, grants/profile/project changes while external source capture is pending | `rust/tests/routes/agent_api.rs`: concurrent creation and template-description tests; `rust/src/tasks/agent_api.rs::retirement_admission_tests`: pre-feature hash, direct admit/capture/write authority recheck, and paused concurrent-winner replay. These assert one task/control/audit and no side effects after revoked authority. |
| Lifecycle commands, stale revisions, durable receipts, in-flight duplicate command, notes, duplicate provenance, queued prerequisites, dependencies, archive/delivery ownership | `rust/tests/routes/agent_api.rs`: command receipt/revision, dependency and lifecycle tests; `rust/src/tasks/agent_api.rs::retirement_admission_tests::in_flight_command_replay_is_held_and_other_key_loses_revision`; native task, archive and delivery operation tests. |
| Task projections, stored source and delivery filters, conditional polling, compact summary and 100-task response budget | `rust/tests/routes/agent_api.rs`: task listing, filtering and paging, summary field projection, ETag/If-Match, and `hundred_task_summary_stays_under_twenty_kibibytes`. |
| GitHub delivery observation, stale/failed checks, merge state, authoritative wait rechecks, no pane/session mirror gate | `rust/src/delivery/operations.rs` delivery observation and retry tests, `rust/tests/routes/agent_api.rs` task read tests, and native archive/delivery tests. |
| Whoami/capabilities/schema/MCP command advertisement and delivery configuration | `rust/tests/routes/agent_api.rs::identity_capabilities_contract_and_discovery_follow_live_grants`, `rust/src/integrations/suplex/runtime.rs` MCP runtime tests, and `rust/tests/contract_parity.rs`. |

The old test harness used injectable TypeScript services to force source-capture pauses and command interleavings. The native checks exercise the equivalent internal admit/capture/write and receipt-claim seams directly, while HTTP tests verify the published result. No TypeScript backend process is required by these checks.
