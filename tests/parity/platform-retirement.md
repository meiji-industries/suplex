# Platform test retirement

The TypeScript platform implementation and its injection helpers are retired after the native checks below. Frontend health/onboarding tests, the Python resource-lock test, and historical SQL assertions remain executable without backend imports.

| Removed TypeScript tests | Native coverage or retired implementation |
| --- | --- |
| `database`, `database-after-commit`, `diagnostics` | `platform::database::{tests,migration_regressions}` checks WAL/reopen, all six readable schema states, migration counts, locked/query-only writes, read-only inspection without creating or migrating, collision rollback, nested commit callbacks, rollback and panic. `cli::tests` checks doctor/task output and required versus optional health. |
| `config`, `setup`, `development` | Configuration address/port unit tests, `native_lifecycle` environment precedence/local binding/rejected public host tests, and `platform::setup` private atomic environment writes with unrelated settings preserved. `platform::development` proves company seeding is idempotent. Node version checks disappear with the Node engine. |
| `install-stages` | `native_install` tests Xcode license accept/cancel, broken installed Git, stale Herdr server restart, and download failure. `native_lifecycle` verifies the manifest/data stage. Both Apple architectures have actual unsigned package/install smoke coverage. |
| `factory-reset` | `http::routes::admin_platform::tests::factory_reset_waits_for_live_sessions_then_restores_a_first_start_database` preserves active work refusal, canceled-session reset, removed accounts/artifacts/provider state, external worktree bytes, and fresh onboarding. |
| `runtime`, `process-manager` | `platform::supervisor` requires HTTP readiness and rejects stale PID identity; `native_lifecycle` proves start, restart after child exit, rediscovery after missing registry, and owned stop. `runtimes::process`, `runtimes::headless`, and `tasks::archive` cover exact executable/argv/start-time/group identity, unknown ownership, escalation, retained groups, and recreated observations. Inspection fixes the locale to C. Node entry paths and legacy process-registry schemas are removed. |
| `self-update.integration`, `update`, `supervisor-packaged` | Six `native_update` real-Git/process tests cover dirty nonoverlap, overlap/divergence, failed install retry, concurrent single flight, stale apply state, running revision versus checkout revision, failed readiness/rollback/retry, and cancellation of the owned install group. `http::routes::update` checks authority and capabilities. Native updater remote identity and bounded output-pipe tests remain. Desktop smoke checks packaged update behavior. |
| `health`, `host-health`, `host-dependencies` | `http::routes::health` checks live owned readiness independently of optional providers, disk settings changes, query/context authority and Tailnet names. `platform::health` checks unavailable storage and malformed Tailnet observations; database health and provider readiness have their own native suites. Native source control uses libgit2 and GitHub API authentication; pnpm/Git CLI health probes and the old ten-second backend cache no longer exist. |
| `executable-resolver` | Native provider readiness and Codex/Claude/OpenCode runtime suites preserve explicit executable selection, PATH/standard installation discovery, absence and dedicated environments. |
| `logging`, `http-infrastructure` | `http::logging::tests::requests_and_failures_are_correlated_without_credentials` exercises real HTTP success/mutation/internal error/expected rejection, levels, timing, request correlation, generic 500 response and secret redaction. It writes through the existing bounded system event sink. Pino adapters and ANSI developer formatting are retired; native logs are plain text. |
| `logs-viewer`, `redaction` | `platform::log_viewer` preserves merged time order, task/URL/error/since filters, hidden debug requests and diagnostic fields; `SUPLEX_LOG_REQUESTS=1` shows debug requests. `platform::redaction` preserves nested credential-key/value masking and command-output redaction. |
| `system-events`, `system-event-transport`, `system-events-api` | `platform::system_events` and `platform::system_event_transport` retain bounded/private/redacted records, rotation/age/total bytes, corrupt-segment recovery, producer identity, malformed socket input and restart. Native update-route/client-report and coordination queue tests cover causal IDs and committed Start/dependent admission. |
| `command-runner` | The generic Node runner and Pino stream adapter are removed. Native runtime/headless/archive tests prove ownership and process termination; `native_update` cancellation proves the owned installer group stops. `platform::update::tests::descendant_output_cannot_keep_a_finished_update_command_pending` preserves the escaped/inherited-output-pipe bound. Command logging goes through the native redaction/event checks. |
| `schemas`, `entrypoint` | The frontend `HealthSnapshotSchema` rejection stays in `system-health.test.ts`; malformed Tailnet observations are native. Node entrypoint discovery and the obsolete process registry schema have no remaining callers or native representation. |

`issue-timeline-events.test.ts` now executes immutable historical SQL through Node's built-in SQLite. Its timeline ordering/row-preservation assertion remains; migration runner idempotence is tested in Rust against real applied ledgers instead of manufacturing a completed ledger around a partially applied database.

Verification: 50 native platform-filtered tests, 4 installer integrations, 3 lifecycle integrations, 6 update integrations, and the HTTP logging regression pass. The five retained frontend/SQL/resource tests passed 19 assertions; the added frontend schema rejection passed with its four existing health assertions.
