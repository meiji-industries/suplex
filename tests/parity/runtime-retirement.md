# TypeScript runtime test retirement

The TypeScript production engine is being retired. This ledger maps backend-only test files to native Rust tests before deletion. The TypeScript files are dated implementation evidence; a Rust test must exercise the same user-visible or recovery condition to replace one. Deterministic native tests, browser journeys, installed provider checks, and real Herdr checks are separate evidence layers.

Source comparison revision: `6bb0a43f`. `cargo test --lib` runs the embedded Rust unit and route tests. Paths below are relative to `apps/server/src` unless shown otherwise.

The five Claude files above are retired. `cargo test --lib runtimes::claude_code` passed 25/25 on this checkout. The old live-history test also asserted the identity of a cached JavaScript array; Rust returns an owned value, while the observable completed-line behavior remains covered.

The Codex analytics/transcript, Devin, OpenCode, and Worker evidence files in the table are also retired. `cargo test --lib runtimes::` passed 156/156 native runtime tests on this checkout; the file-by-file mapping above identifies the corresponding assertions.

The archive-session file is retired. `cargo test --lib archive_uses_live_native_and_git_facts_then_commits_once` passed; its native operation test covers all six TS session-ownership cases against the database and native server fixture.

The Worker Git guard file is retired. `cargo test --lib runtimes::git_guard` passed 4/4, including the new filesystem replacement and local-remote rebase regressions.

The deterministic and real Herdr archive-display files are retired. `cargo test --lib tasks::archive::displays` passed 12 tests with one ignored live test. The live test compiles but was not run: `HERDR_ENV` is absent, and `HERDR.md` permits Herdr control only from a managed pane. Run its ignored Rust test from a Herdr-managed pane to renew the external proof.

The Worker replacement service and API files are retired. `cargo test --lib worker_and_coordinator_replacement_preserve_handoffs_and_native_readiness` and `cargo test --lib local_backlog_create_fetches_git_and_returns_full_task_shape` both passed with the new policy, stopped-session, authenticated-route, and limit-pause assertions.

The workflow-intake file is retired. `cargo test --lib workflow` passed 16/16, `advisor_reports` 2/2, and `standard_request_hash` 1/1. The focused `repair_pull_request_rejects_closed_and_foreign_sources_and_pins_the_open_head` native source test also passed. Existing native template and migration fixture tests provide the remaining persisted/legacy coverage; they were not rerun in this focused wave.

The Root bridge file is retired. `coordination::root_stdio` and `coordination::root_bridge` native tests cover the tool schema, argument validation, binding identity and token handling. Private-binary `root-image`, `root-worker-evidence`, `root-worker-replacement`, and `root-delivery-inspection` journeys passed against Rust MCP stdio, including invalid-token rejection before initialization and durable task-scoped operations. The native invalid evidence query and pull request text table was added before retirement.

The task-worktree file is retired. `cargo test --lib tasks::worktree::tests` passed 4/4 after a bounded native retry fixed a real concurrent Git branch lock race. Focused native `stop_rescans_and_stops_a_detached_child_created_during_shutdown`, `retired_session_cleanup_preserves_another_session_in_the_same_worktree`, and `dispatch_recovery_stops_the_old_execution_without_stopping_its_replacement` tests passed. The worktree tests assert exact Git status, conflict/rebase files, retained out-of-band commit bytes, foreign directory contents, and convergence of simultaneous creation; the archive operation test covers detached worktree process ownership.

The task-host file is retired. The native sweep reads delivery state before deciding whether an active task needs worktree preparation or a native session, and keeps delivery-wait observation separate from ordinary observation. Host/preparation tests cover native dispatch, durable claims, setup context and failure recovery; issue-context tests cover provider failures. The worktree conflicted-rebase test and delivered-PR refresh integration were added in this retirement wave. The missing one-minute refresh after all sessions stop was fixed in `tasks::host::tests::delivered_pull_refresh_starts_immediately_retries_and_stops_with_host`, which passed; the native delivered-PR integration also covers in-flight resumption, missing receipts, provider failures, reopening, and merged facts.

The Codex runtime file is retired. `cargo test --lib runtimes::codex` passed 27/27. Native dispatch tests use a real fake executable and assert Worker/Coordinator/Advisor scope, bridge secrets, claim ordering, and read/write policy. Invocation, thread, headless process, transcript, evidence, and display tests cover the remaining native lifecycle. The audit found that a dead resumed rollout had no production call to clear its thread; `runtime::tests::only_an_unresumable_resume_forgets_the_persisted_codex_thread` now verifies this recovery while preserving a thread after authentication failure.

The Root delegation file is retired. The native store test passed with assertions that a newer Worker generation remains authoritative even when an older session has a later timestamp, and cleanup of that conversation blocks reuse without falling back. Existing native store tests cover duplicate rejection, session/turn reuse, and operation ownership; host recovery tests cover a single wake after completion or interruption without replay. The native Worker evidence reader tests bounded cursors and native failure text, while pinned prompt tests preserve assignment and review wording.

The GitHub delivery file is retired. Native exact-head queue and bounded retry tests passed; the branch 404/outage test separately verifies that an outage cannot masquerade as absence. The Rust integration uses typed HTTP rather than the deleted `gh` executable, so the old CLI path and argument-vector assertions have no native behavior to preserve. Native normalization and fake GitHub tests retain checks, issue pagination/validation, and merge refusal behavior. A direct release merge still uses repository-supported merge settings and exact-head REST input.

The Coordinator replacement service and API files are retired. `worker_and_coordinator_replacement_preserve_handoffs_and_native_readiness` verifies the durable replacement chain, preserved old profile, answer/note/direction handoff, exact frozen prompt bytes and hashes, pending question identity, and cleanup readiness. The authenticated task route regression now also checks an unauthenticated request, a foreign session, a 20,000-character handoff, exact idempotent response, and a changed-intent conflict; its focused test passed. Stale Coordinator identity, active/paused task policy, provider allowlist, and limit-decision checks execute in the native replacement path. The old service tests injected TypeScript harness races; native host recovery and turn ownership tests exercise the corresponding process/session boundaries.

The three Root controller lifecycle, limit, and recovery files are retired. Native store and host tests exercise the durable admission transaction, interrupted-turn wake, answer/question identity, session owner claims, restart, and cancellation. The added cancellation regression checks that a late Worker result cannot record a receipt or wake Coordinator. Limit coverage combines a pinned TypeScript budget/turn table with native usage snapshots, missing/unpriced pricing, corrected spend, durable pause, and exact limit-answer prompts. Native OpenCode session tests prove that ambiguous or admitted prompts are not replayed after a lost acknowledgment; host and headless tests cover process identity and dispatch ownership. Display metadata is advisory in the native dispatch path.

The four remaining workflow and delivery files are retired. Paired Planner reservation, distinct Advisor roles, report validation and reconciliation, frozen workflow prompts, direct/combined Worker obligations, latest same-role review gating, and exact range comparison have native unit and store tests. Delivery uses real Git observations and a loopback GitHub in the native integration tests, including exact-head merge refusal and accepted outcomes. The added pull-discovery test covers closed history, pinned retargeting, foreign forks, and ambiguity. The added final-commit test reopens the database and proves that a newer rejecting review, active delegate, or cancellation prevents completion; a clean reviewed state commits once. The native mutation path separately rechecks current Git/GitHub state and Root/tool ownership before push, ready, merge, and completion. TypeScript harness call-order assertions refer to the removed adapter and are replaced by these native transaction and observed-state checks.
