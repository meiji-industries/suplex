# Rust JSON byte spike (2026-09-24)

Historical port investigation. Source locations, fixture counts, and remaining
work below describe the 2026-09-24 snapshot, not the current Rust release state.

The four persisted SHA-256 inputs are `src/tasks/repository.ts:38` and
`src/tasks/tasks.ts:383,984,1050`. The first three store hex digests; the task
revision at line 1050 uses base64url. The fixtures in
`tests/parity/hash-bytes` are generated by Node's `JSON.parse` and
`JSON.stringify`. The repository fixture also asserts against the live
`taskRequestHash` function. The other three fixtures reproduce their input
shapes and field ordering from those call sites; their private methods are not
invoked by this spike.

`serde_json` with `preserve_order` is insufficient. It preserves insertion
order, while JavaScript sorts array-index property names before other keys.
JavaScript also rounds JSON numbers to binary64, formats exponents and negative
zero differently, accepts an overflow exponent and stringifies it as `null`,
and preserves escaped lone UTF-16 surrogates. `serde_json::Value` cannot hold
the latter two inputs. Four representative site fixtures and four edge
fixtures establish these differences. `rust/src/shared/js_json.rs` implements
the limited byte serializer, including a raw JSON path that retains UTF-16
code units and JavaScript number behavior. All eight fixtures pass in Rust.

This spike establishes hash-byte feasibility, not HTTP acceptance parity. The
raw parser and serializer are not yet wired into Rust routes. A route that
first parses with `serde_json::Value` will still reject lone surrogates and
overflow exponents that the TypeScript service accepts. Rust validators must
also count UTF-16 code units for Zod string lengths; the serializer exposes
`utf16_len` and tests an astral character. These are required integration
tasks before any affected route is marked verified.

The Zod generator currently writes 1,682 fixtures for 195 exported schema
names across 13 HTTP contract modules. Each has an accepted representative;
object cases also exercise an unknown key and a first-field omission/null.
The Rust validator currently ports five auth schemas and passes all 39 of
their fixtures. The remaining 190 exported schema names are unported in Rust.
`tests/parity/boundaries.json` inventories 158 syntactic validation boundaries
in the HTTP files and their direct schema dependencies: four coercions, three
passthrough calls, one preprocess, 13 refinements, 131 strict calls, three
strip calls, two super-refinements, and one transform. Of those, 78 are in the
HTTP files themselves. This is an inventory, not proof that every branch has
a parity case yet.

The TypeScript generators were retired with the engine. Their frozen outputs
remain checked by `cargo test --manifest-path rust/Cargo.toml --test contract_parity`
and `cargo test --manifest-path rust/Cargo.toml --test hash_bytes`.
